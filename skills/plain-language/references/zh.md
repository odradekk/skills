# 中文写作参考

本文件适用于所有中文文本：聊天、代码注释、文档、commit message 和标识符。已有通行说法的地方用通行说法，不自己造词。

## 1. 篇章：冗余和跳跃

判断：先用一句话说出全文的主要观点，再逐段问两件事：这一段和主要观点或上一段是什么关系？读者需要它吗？内容越多不代表越好，多余的内容会把重点淹没。

| 常见写法 | 改法 |
|---|---|
| 开头先铺垫背景（“在回答这个问题之前，先介绍一下……”） | 先给结论或回答；背景只留读者理解结论必需的部分 |
| 结尾把正文再总结一遍 | 删掉，正文已经说清楚了 |
| 同一条提醒在几处重复出现 | 只在最相关的地方说一次 |
| 想到的点全部列出，不分主次 | 只留和读者问题有关的点；重要的放在前面、写得详细，次要的一句带过或删掉 |
| 段落之间换了话题，却没有交代两者的关系 | 补一句说明关系，或者调整顺序；接不上的内容移走或删掉 |
| 用“首先、其次、最后”串起几件其实没有先后关系的事 | 按真实的关系组织（因果、先后、对比）；没有关系就分开写 |
| 先讲过程细节，最后才给结论 | 结论放在前面，细节按需要补充 |

## 2. 逐字直译的英文术语

判断：中文开发者平时会这么说吗？有通行译法就用通行译法；开发者习惯直接说英文的词（commit、PR、merge、rebase、issue、hook、CI 等），保留英文。

| 常见写法 | 改为 |
|---|---|
| 门、门禁、硬门、闸、阶段闸 | 测试、检查、阻断性检查、阶段检查点 |
| 守卫（指校验代码） | 校验、检查、防护代码 |
| 锚、弱锚、锚表、结构锚、追溯锚 | 目标、指标、基准、参考目标 |
| 靶、靶文件、靶面 | 目标文件、改动文件、覆盖范围 |
| 臂 | 分支 |
| 杀 | 完成、结束、终止（进程）、取消 |
| 接线、接线锁 | 装配、依赖接入 |
| 上下文墙 | 上下文超限 |
| 暗耦合 | 隐式耦合、隐藏依赖 |

英文句式的直译也属于这一类：

| 常见写法 | 改为 |
|---|---|
| 做出一个决定 | 决定 |
| 基于这个原因，…… | 因为……，…… |
| 对于这个函数来说，它会…… | 这个函数会…… |
| 在配置缺失的情况下 | 如果缺少配置 |
| 作为一个缓存层，它…… | 它是缓存层，…… |
| 配置被加载器读取 | 加载器读取配置 |
| 提供了导出的能力 | 可以导出、支持导出 |

## 3. 挪用其他领域的专业词

判断：这个词在本领域有这个意思吗？从法律、医学、军事、竞赛等领域借来的词，换成本领域的说法。

| 常见写法 | 改为 |
|---|---|
| 判据 | 标准、判断条件 |
| 裁定 | 结论、决定 |
| 证伪、证伪探针 | 反向验证、故意注入错误来验证 |
| 鉴别力 | 区分能力、能否发现回归 |
| 号段 | 编号区间 |
| 简报 | 任务说明、工单说明 |
| 派单、派票、切票 | 分配任务、拆任务 |
| 整改、退回整改 | 返工、修改 |
| 对拍 | 基线比对、逐条比对 |
| 票面、本票 | 工单内容、这张工单 |
| 形态（指写法） | 形式、写法、变体 |

## 4. 互联网黑话

判断：这个词能换成一个具体的动作或结果吗？能换就换。

| 常见写法 | 改为 |
|---|---|
| 落地 | 实现、上线 |
| 收口 | 合并、收尾 |
| 体量 | 规模 |
| 口径 | 统计方式 |
| 点名 | 明确指出 |
| 漂移（指不一致） | 不一致 |
| 收敛 | 确定下来、逐步减少 |
| 抓手 | 具体做法 |
| 对齐、拉齐 | 统一、确认一致 |
| 赋能 | 支持、帮助 |
| 颗粒度 | 粒度、细致程度 |
| 闭环 | 跟进到结束、形成完整流程 |

## 5. 自造缩写、名词堆叠和私有标签

判断：读者第一次看到这个词时，能看懂它指什么吗？“方案 B”“Q3”“第 2 步”这类标签是工作过程中给自己用的，读者没见过。看不懂的词换成它指的内容，缩写和名词堆叠写成完整的句子，数字带上单位和主语。

| 常见写法 | 改为 |
|---|---|
| 全拦、零红、条全拦零红、零弱锚、三方归一、无引擎重跑 | 写成完整句子，例如「573 个变异全部被拦截，0 跳过，0 失败」 |
| 按方案 B 做 | 按先建索引、再迁移数据的做法 |
| Q3 的结论 | 关于缓存失效时间的结论 |
| 第 2 步改完了 | 数据库迁移脚本改完了 |
| P0 问题 | 会导致数据丢失的问题 |

## 6. 口癖

判断：同一个句式或词在一次回复、一篇文档里出现两次以上；或者删掉以后意思不变。

| 常见写法 | 改法 |
|---|---|
| 不是 X，而是 Y | 直接说 Y；只有读者确实可能误以为是 X 时才保留对比 |
| 值得注意的是、需要指出的是、需要强调的是 | 删掉，直接说内容 |
| 总的来说、简单来说、一句话总结、换句话说 | 删掉；需要总结时直接写结论 |
| 本质上、核心在于、关键在于 | 删掉，或者说出具体是哪一点 |
| 这不仅……更…… | 分成两句，各说一件事 |
| 让我们……、接下来我将…… | 直接做，直接说结果 |
| 好问题、您说得对、非常好的想法 | 删掉，直接回答 |
| 硬凑成三项的排比 | 实际有几项就写几项 |
| 打造、助力、彰显、凸显、深度、全面 | 用具体的动词，说清楚做了什么、做到了什么程度 |

## 7. 名词化和空动词

判断：句子里的动作是不是藏在名词里？把动作还原成动词。

| 常见写法 | 改为 |
|---|---|
| 进行优化、进行了修改 | 优化、修改了 |
| 对配置进行校验 | 校验配置 |
| 实现……的目标、达到……的效果 | 直接说做到了什么 |
| 做了一个缓存的处理 | 加了缓存 |
| 完成了迁移工作 | 迁移完了 |

## 8. 推理过程的残留

判断：这句话是在讲结果，还是在讲你是怎么得出结果的？读者要的是结果。

| 常见写法 | 改为 |
|---|---|
| 我先查了……，然后发现…… | 直接写查到的结果 |
| 原先是……，现在不再…… | 写现在的状态；确实需要对比时，说清楚改了什么 |
| 如前所述、上面提到的方案 | 直接说那个方案的内容 |
| 经过评审、在这一轮里 | 删掉，写结论 |

## 9. 标点和格式

- 中文用全角标点。
- 中文引号“”和破折号——是正常标点，照常使用。破折号容易用多：一段里最多一处，能用逗号或句号的地方就不用。
- 不用 emoji。
- 加粗只留给读者需要先看到的词，不要每段都加粗。
- 三句话能说完的内容不加小标题；平行的几项才用列表，需要对比时才用表格。
- 中英文之间是否加空格、括号用全角还是半角，按项目文风。

## 10. 同一概念只用一个词

同一个概念在整个项目里只用一个词。不要像“存根”和“桩”那样两个词混用：先定一个，再全程沿用。

找不到通行说法时，用一个描述性的短语，例如“只因为改同一批文件而产生的阻塞”，并且全文都用这个短语。

## 例外

领域固有名词和通行译法不在禁用之列：mutation testing 的“变异”、Facade 的“门面”、项目源码里的目录名和游戏文本用语（如“口上”“台词”）照常使用。
